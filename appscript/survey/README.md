# DEF CON 34 survey backend

Separate from `appscript/Code.gs`, which is the Alphanaut feedback backend —
two independent Apps Script projects, two Sheets, two deployments.

Apps Script Web App that validates survey submissions and appends them to a
Google Sheet. Paired with the `/survey` route in this repo.

## Files

| File | Notes |
|---|---|
| `Code.gs` | Endpoint, validation, Turnstile check, sheet append |
| `Schema.gs` | **Generated.** Do not hand-edit — see below |
| `appsscript.json` | Manifest; pins the web app access mode and OAuth scopes |

## Setup

1. Create a Google Sheet for responses and copy its ID from the URL.
2. Create a new Apps Script project (script.google.com).
3. Enable **Project Settings → Show "appsscript.json" manifest file**, then
   paste in the three files from this directory.
4. Under **Project Settings → Script Properties**, add:

   | Property | Value |
   |---|---|
   | `SHEET_ID` | The spreadsheet ID from step 1 |
   | `TURNSTILE_SECRET` | Cloudflare Turnstile secret key |

   The endpoint **fails closed**: with no `TURNSTILE_SECRET` set, every
   submission is rejected. To run without a bot check during local development,
   also add `ALLOW_INSECURE_TURNSTILE_BYPASS` = `true` — never set this on the
   production deployment. Rows collected under the bypass are stamped
   `bot_check = skipped` so unchecked data stays identifiable.

5. Run `rebuildCodebook` once from the editor to populate the `codebook` tab and
   to trigger the OAuth consent prompt.
6. **Deploy → New deployment → Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
7. Copy the `/exec` URL into the flasher's `SURVEY_WEBHOOK_URL` environment
   variable, and the Turnstile *site* key into `TURNSTILE_SITE_KEY`.

### Why "Anyone" and not "Anyone with a Google Account"

"Anyone with a Google Account" forces an interactive Google login. A
cross-origin `fetch` from `defcon.meshtastic.org` cannot satisfy that, so every
submission would fail — and it would also break the survey's anonymity promise.
"Anyone" is correct here and is safe: the script only appends validated rows and
never reads data back out.

Note also that `Session.getActiveUser().getEmail()` returns an empty string for
consumer Google accounts outside the script owner's Workspace domain, so the
"verified email" behaviour Google Forms offers is not available to a web app
even if we wanted it. This survey is anonymous by design.

## Regenerating Schema.gs

`Schema.gs` mirrors `components/survey/schema.ts` so the server validates
against exactly the questions the client rendered. Never edit it by hand — a
too-permissive server allowlist fails open and silently accepts junk.

```sh
pnpm run survey:schema   # from the repo root
```

Then paste the output into the Apps Script project. Bump `SCHEMA_VERSION` in
`schema.ts` **before** regenerating whenever questions or option codes change:
the endpoint rejects mismatched versions, which is what stops a stale cached
page from writing values into columns that now mean something else.

## Data layout

The `responses` tab holds one row per submission:

- `submission_id`, `submitted_at` (server UTC), `schema_version`, `duration_ms`,
  `bot_check`
- One column per question, keyed by the permanent question ID
- For every multi-select, an additional boolean column per option
  (`q_issues__no_delivery`, …) so cross-tabs and pivots need no string parsing

The `codebook` tab maps every question ID and option code to its prose, and is
regenerated by running `rebuildCodebook`.

`bot_check` records how the submission was screened: `verified` (Turnstile
passed) or `skipped` (no secret configured — development only). Production rows
should all read `verified`; any `skipped` rows in production mean the secret was
missing and that data was collected without a bot check.

## Testing the endpoint with curl

```sh
curl -sL 'https://script.google.com/macros/s/DEPLOY_ID/exec' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  -d '{"schemaVersion":1,"durationMs":120000,"turnstileToken":"","hp":"",
       "answers":{"q_attend":"venue","q_powered":"whole_event",
                  "q_cohort":"default_longfast","q_devices":["tdeck"],
                  "q_issues":["none"],"q_next_year":"probably"}}'
```

**Do not add `-X POST`.** curl applies `-X` to every request in a redirect
chain. Apps Script 302-redirects `/exec` to `script.googleusercontent.com`,
which serves GET only, so forcing POST through the redirect returns a Google
Drive "unable to open the file" HTML page that looks exactly like a permissions
failure and has nothing to do with your script. `-d` alone sets POST on the
first request and lets curl downgrade the redirect to GET correctly.

Browsers do the same downgrade automatically, so the survey's own `fetch` call
is unaffected.

Note that `durationMs` must be at least `MIN_FILL_MS` (20s) or the submission is
rejected as too fast to be human.

## Troubleshooting a deployment

| Symptom | Cause |
|---|---|
| Drive "unable to open the file" on POST, but GET works | `-X POST` in curl (see above) |
| Both GET and POST fail, even for the owner | Deployment pinned to a stale code version. **Manage deployments → pencil → Version: New version** |
| Works signed in, fails anonymously | Access is not set to **Anyone**, or Workspace policy blocks anonymous sharing |
| Code changes have no effect | Editing `Code.gs` does not update the live endpoint — you must deploy a new version every time |

The `/dev` URL under **Deploy → Test deployments** always runs the latest saved
code as you, bypassing versions and access settings. If `/dev` works and `/exec`
does not, the code is fine and the deployment config is wrong.

## Known limitation: no drop-off measurement

The survey posts only once, at the end. People who abandon partway through, and
people screened out at the first question, never reach a submit and so leave no
row. The sheet therefore contains completed, screened-in responses only, and
cannot tell you your completion rate or where people gave up. Measuring that
would require posting partial state as respondents advance, which was
deliberately not built — it complicates the anonymity story for limited value.
